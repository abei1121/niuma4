# 人生运势历全栈架构与商业闭环规范

## 一、 系统定位与命主核心哲学

《人生运势历》（`obs.xiaojiucai.pro`）是融合正统紫微斗数命理算法、动态流日气机真机计算与造物主人生剧本流式推演的高性能全栈工程。

### 1. 人生剧本哲学 (The Life Script Philosophy)
* **立意本质**：人这一生就是一个全新的剧本。紫微斗数排盘并非定死宿命，而只是让命主提前看清人生的「目录大纲」；剧本的走向、演法与关键抉择，始终牢牢掌握在命主自己手中。
* **法定入口命名**：顶栏核心主按钮法定唯一定名「查看你的人生剧本」，严禁擅自更名为其他生硬工具词汇，牢固守护这一立意。

### 2. 排盘严谨玄黑底色铁律 (Strict Obsidian Chart Standard)
* **视觉对比度红线**：首页虽为白玉生宣纸质感，但十二宫排盘视界（Pro 模式）必须绝对坚守高对比度玄黑底色（`#060606`）。
* **严谨命理场域**：白底在移动端与真机上根本看不清几十颗星曜与复杂飞星光辉。排盘是极端严谨严肃的数术场域，唯有玄黑高对比度才能让用户看清大局与细节，严禁将排盘界面篡改为浅白底色。

### 3. 星曜正统繁体铁律 (Orthodox Traditional Chinese Star Canon)
* **正统智慧承载**：星曜名与四化是中华正统命理智慧的最高结晶，盘面上所有星曜（紫微、天機、太陽、武曲、天同、廉貞、文昌、文曲等）及四化（祿、權、科、忌）必须强制采用正统中文繁体显示，绝不可降阶。
* **动态多语言边界**：国际化动态多语言仅作用于外围功能按钮、操作引导、解盘批语与使用说明，星曜本体神髓保持正统繁体不变。

## 二、 商业计费与天命能量治理新规

### 1. 差异化计费模型
* **全命盘全局深度推演**：单次消耗 **6 点天命能量**。
* **后续导师解惑追问**：单次消耗 **1 点天命能量**。

### 2. 彻底废除静默扣费与进入扣费
* 进入人生剧本模态默认展示「封印解封 · 人生大纲推演准备大厅」（`CreatorScriptStartGate.tsx`），清晰呈现派系特色、能量余额与明细规则。
* 必须由用户主动点击「解封天命 · 开启全盘深度推演」按钮后方可发起计算与扣费。
* 若天命能量不足 6 点，按钮置灰并友好提示差额，严防透支或服务端报错。

### 3. 历史推演用户终身免费特权
* 推演完成后，全篇剧本自动哈希归档保存于客户端。
* 已生成过剧本的用户再次进入时，系统秒级调取历史档案，直接呈现完整命书，消耗 0 能量。
* 顶栏显式展示「档案已存 · 终身永久免费阅览」状态。
* 用户主动触发重新推演时，提供原生二次确认机制，防范误触重复扣费。

### 4. 三层梯队会员体系
* **非会员 (Free)**：能量 0 点，进入准备大厅展示绑定激活码或连接俱乐部会员卡引导。
* **激活码会员 (Activation Code)**：单码 30 点专属天命能量，扣完即止，严格执行 1 机 1 卡客户端绑定。
* **小韭菜俱乐部会员卡 (Club Pass Holder)**：每日子时自动重置回满 10 点专属能量，每日支持全盘推演与多次追问。

## 三、 商业机密绝对隔离与封闭防护规范 (Zero-BYOK Policy)

### 1. 废除用户自定义 API (BYOK) 的底层动因
* **蜜罐服务器抓包风险**：若允许用户自定义 Base URL，有心用户可配置抓包地址，服务端发起的请求体将明文暴露完整的宗师核心提示词（中州派十四主星赋性、四重叠宫算法与钦天派自化串联公式）。
* **第三方中转平台审计风险**：聚合 API 平台及中转站后台普遍记录 Request Body，导致专有提示词外泄。

### 2. 全闭环安全架构
* **物理下线前端配置**：彻底删除 `NftCustomApiPanel.tsx`，前端不保留任何 API Key、Base URL 或 Model 输入框。
* **全局文案清洗**：移除所有语言包（中文简体、繁体、香港繁体、英文等）与组件中关于“接入自定义 API”的表述。
* **服务端私有闭环**：所有推演与追问请求统一收拢至服务端私密引擎直接调度，对外只下发流式渲染文本，商业提示词绝不出内网。
* **防泄密绝杀指令**：在中州派、钦天派及追问宗师提示词中注入安全红线指令，彻底拦截通过 Prompt Injection 越狱套话的企图。

## 四、 跨机协同研发与自动化流水线

### 1. 硬件角色分工
* **Mac mini M2 (牛马4号, `192.168.1.3`)**：承担前端 TypeScript 严苛语义检查、Vite 极速编译打包（约 3 秒）与 Git 仓库管理。
* **Intel Celeron J3710 (牛马2号, `192.168.1.182`)**：专职生产宿主、Nginx 静态 Brotli/Gzip 预压缩直发与纯 Rust 鉴权流式微服务（`127.0.0.1:8096`）24/7 守护。

### 2. 自动化部署发布 SOP
在 Mac mini M2 工程目录 `/Users/hi/niuma/projects/obsxiaojiucai/` 执行：
```bash
./deploy.sh "commit 提交信息"
```
执行链路：
1. 自动暂存并 rebase 远端最新代码；
2. Mac 本地完成 `npm run build` 极速生产构建；
3. Git 自动提交并推送到 GitHub 远端；
4. SSH 触发 J3710 生产仓 `git pull`；
5. rsync 原子推流静态产物至生产机 `dist/`；
6. 触发 J3710 执行 `sudo nginx -t && sudo systemctl reload nginx` 平滑热上线。
